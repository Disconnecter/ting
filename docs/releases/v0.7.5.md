# Ting 0.7.5

## New

- **Links in micro-app results.** Markdown output (`output.as: markdown`) now
  shows `[text](target)` links. The target is an `http`, `https` or `mailto`
  URL, a `file` URL or an absolute path (`/…` or `~/…`); a target with spaces is
  written as `[text](<~/My Folder>)`. A click opens a web or mail link, opens a
  folder in Finder, and shows any other file selected in Finder. A file link
  never opens the file itself, so a result from the web or an AI cannot start a
  script or an app. Other targets stay plain text.
- Links are underlined. A web or mail link has the link colour; a file link
  keeps the colour of the text around it, with a faint underline, so a list of
  files stays readable.
- The first click on a link shows a warning in the result panel: a link comes
  from the micro-app's output, which can carry text from the web or an AI, and
  may lead to a harmful site. The warning shows where the link goes. **Open
  Link** (Return) follows it and the warning does not show again; **Cancel**
  (Esc) closes the warning and leaves the result open.
- **Links in a monospaced tree.** A code block fenced as ```` ```links ```` keeps
  its monospaced lines, so a `├──` tree stays aligned, and its links work. See
  [the format](../micro-apps/FORMAT.md).

## Fix

- The release scripts build and check with the Xcode 27 toolchain.
  `package_app.sh` builds with the native build system, and `release.sh` checks
  one architecture per `lipo` call, as the newer `lipo` refuses several after
  `-verify_arch`. The service tests find `Sparkle.framework` under Swift Build
  again.

## Upgrade

A downloaded copy: choose **Check for Updates…** in Ting. A Homebrew copy:
choose **Update Ting via Homebrew…** in Ting's menu. Settings, bindings,
micro-apps and permissions are preserved. Requires macOS 14 or later; the
signed, notarized and stapled universal app supports Apple Silicon and Intel.
